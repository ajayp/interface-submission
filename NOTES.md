# NOTES

Submission folder: `my_solution/` (entry point `solution.py`, `build()`). Python 3.11; `pip install -r my_solution/requirements.txt`.

## API keys and cost

Needs `OPENAI_API_KEY` (paid OpenAI API) with access to `gpt-6-luna`, the Decisions API (`/v1/decisions`) and `text-embedding-3-small`. Loading the five snapshots (untimed) takes about 3 minutes and about $0.10, mostly one model call per distinct rate table. Each answer makes three small calls (question labels from the Decisions API, one embedding, the answer); a rate or fee question that the rate tables don't answer makes a fourth, when it falls back to text search; `conflicts()` makes about 77 small calls once. Answer-time model calls ask OpenAI for its faster service tier (about 2x the price per answer call, not confirmed for every account); if the account refuses that option (HTTP 400, 403, 404 or 422) the call is retried once on the default tier, and loading-time calls always use the default tier. Without a key the system still runs on search alone, but refusals are not possible and the score is much lower (0.34 on the public set).

## How it works

At loading, each page is split by heading (every table row is its own piece), each website copy gets a keyword index and an embedding-window index (both built while loading, so no timed answer pays for them), and every rate table is read once into facts (product, term, tier, metric, value, source page, page type, dates). At answer time, one Decisions call labels the question (section, rate type, whether a past date or a change is asked). Rate and fee questions are answered from the facts, keeping only the winning value per product and tier, so stale values never reach the model. Other questions use the best keyword pieces plus a few embedding-search pieces (600-character windows cut from the same pieces; their vectors are committed in `my_solution/.embed_cache` and are never built while answering: if a snapshot has a window whose vector is missing from that file, window search is silently off for that snapshot and the question gets keyword pieces only). The answer model returns one value, the right tier, the sources, and "I don't know" (no numbers) when the website does not say. Questions about what changed ("what was it before?", "did it change since May?") are searched in every website copy and answered with each value and the dates of the copies it appeared in. `conflicts()` reads the newest copy only: rate tables are read by code, rate sentences by one small model call each, and counts about the credit union (branches, employees, members, assets, counties served) by fixed patterns. Two values are the same fact only if rate type, term, tier, model years and product words agree, never judged by the numbers. Qualifiers such as tier, term, personal vs business or rate vs APY make different facts, not conflicts. Spelling: a question word the website never uses is matched to a website word one edit away (the word list is learned from the snapshots while they load) and added to the search next to the member's own word; the question text the model sees is unchanged, there is no extra model call, and `MY_SOLUTION_SPELLFIX=0` turns it off.

## How "current" is decided

Without a date, the answer comes from the newest copy. With a date (`as_of`, or a date in the question that describes the website: "as of June 2026", "back in May 2026", or a rate question in the past tense; a month named without a year, as in "what was the rate in May?", is read as the latest such month not after the newest copy, so 2026), it comes from the latest copy taken on or before that date; a date before the oldest copy (2026-05-12) gets "I don't know". A rate or fee question that names a month with no year counts as dated even without a past-tense verb ("business 12 month cd apy in may"), unless it looks forward ("will", "would", "if I", "next"). A dated answer begins "As of <date>," (not on a "what changed" question, where the date is the start of a comparison) and says when the year was assumed. For a "what changed" question about page text, each copy's embedding-window pieces are added to its keyword pieces. Within a copy, trust goes rate sheets, then product and service pages, then promotion pages, then everything else (news, blog, calculators, PDFs). Between pages of the same type, the later "effective" date wins, then the later publish date. Two decisions: a value that changed between copies with no stale copy left in the newest one is history, not a conflict, and `conflicts()` does not list it; and a fact that exists only on a page missing from the newest snapshot is not answered for a current question, but is answered for a dated question from the snapshot that has the page.

## Results and limits

Public set (40 questions, fresh clean folder, Python 3.11, mostly cold loads as graded (one run reused saved facts), no conflicts gold available locally): on the default answer tier, 3 runs gave accuracy 0.851, 0.851, 0.867 and final score 0.834, 0.839, 0.851; with the faster service tier on answer calls, 2 runs gave accuracy 0.867 and 0.867, final 0.857 and 0.859. All runs: consistency 1.0, 0 stale values, 0 errors, all three should-refuse questions correct. Speed: p50 2.25 to 2.53 s and p95 3.4 to 4.1 s on the default tier; p50 1.83 to 1.90 s and p95 2.9 to 3.2 s with the faster tier. The 2 s full-marks line is not met. One run had a single 8.3 s answer (probably a call that timed out and was retried). Loading takes about 3 minutes and about $0.10 cold. Our own question sets (written by us, not the organizers'): held-out 22 questions 1.0, dated questions 21 questions 0.993. With no API key the run completes without errors and scores 0.34. Our stand-in for the LLM judge gives about 0.81 to 0.82: answers are short on purpose and some references want extra detail.

`conflicts()` returns 42 entries. Against a 12-entry list we wrote by hand without our extraction code it finds 12 of 12 with the right winner on 11 (precision 0.29, because we list each stale mortgage and auto-loan row separately where the hand list folds them into headline rows); against our older 35-row key it finds 35 of 35. We do not know the organizers' granularity, so we kept the rows separate. The members count winner is the newest news release (179,000), not a later PDF figure (182,627).

Accepted misses: dup-049, dup-008 and dup-088 (two readings of the question), dup-104 (the main lobby-hours piece misses the answer window), dup-005 (a range instead of every rate). On the tiny selftest fixture a reworded certificate question ("Current APY on a six month share certificate?") is refused although the plain wording is answered; the real data did not show this with "current" wordings. A rate or fee question the tables do not answer makes a second model call that searches page text (about 1.4 s extra); across 141 of our questions it found a real number 10 times in 25. An answer-call timeout becomes "I don't know" for that question. Facts cover rate tables only; hours, awards and similar prose facts go through text search.
